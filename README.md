# LBOX 판례 검색 서비스 역기획

법률 정보 서비스 LBOX의 판례 검색·상세 화면을 직접 기획하고 구현해 본 웹 프로젝트입니다.

## 주요 기능

- **판례 검색**
  - 검색어로 판례 찾기
  - 사건 유형(민사·형사·행정), 법원명, 선고일 기간으로 걸러 보기
  - 선고일순·조회수순 정렬, 페이지 이동
- **판례 상세 보기**
  - 판결 제목, 사건 정보, 판시사항, 판결요지, 참조조문, 판결문 전문 표시
- **인용 판례 패널**
  - 지금 보는 판례가 인용한 판례 목록을 오른쪽 패널에서 펼쳐 보기
  - 10건이 넘으면 목록 안에서 스크롤
- **판례 비교**
  - 인용 판례를 누르면 화면을 둘로 나눠 원래 판례와 나란히 비교
- **패널 자동 열기**
  - 켜 두면 다음에 판례를 열 때 패널이 자동으로 열림 (브라우저에 저장)
- **오류 페이지**
  - 없는 주소나 없는 판례로 들어가면 오류 안내 화면 표시

## 사용 기술

- React 19.2
- TypeScript 6.0
- Vite 8.3
- Tailwind CSS 4.3
- React Router 7.18
- TanStack Query 5.104 (서버 데이터 캐싱)
- axios 1.20 (API 호출)
- Pretendard (글꼴)
- ESLint 10, Prettier 3.9 (코드 검사·정리)
- Vercel (배포)

### 연동 API

| 기능           | 주소                                   |
| -------------- | -------------------------------------- |
| 판례 검색      | `GET /api/v1/judgments/search`         |
| 판례 상세      | `GET /api/v1/judgments/{id}`           |
| 인용 판례 목록 | `GET /api/v1/judgments/{id}/citations` |

API 문서: https://lbox-backend-production.up.railway.app/swagger-ui/index.html

## 실행 환경

- Node.js: v24.14.1에서 개발했습니다.
- 패키지 매니저: npm
- 브라우저: 최신 Chrome 기준
- 환경 변수: `VITE_API_BASE_URL` (백엔드 서버 주소)

## 설치 및 실행 방법

1. 저장소를 clone합니다.

   ```bash
   git clone https://github.com/Ahyun26/CEOS-MashupDay-Team3-Lbox.git
   cd CEOS-MashupDay-Team3-Lbox
   ```

2. 패키지를 설치합니다.

   ```bash
   npm install
   ```

3. 프로젝트 루트에 `.env` 파일을 만들고 아래 한 줄을 넣습니다. `.env`는 저장소에 올리지 않습니다.

   ```
   VITE_API_BASE_URL=https://lbox-backend-production.up.railway.app
   ```

4. 개발 서버를 실행하고 브라우저에서 http://localhost:5173 에 접속합니다.

   ```bash
   npm run dev
   ```

그 밖의 명령어는 다음과 같습니다.

| 명령어            | 설명                                  |
| ----------------- | ------------------------------------- |
| `npm run build`   | 배포용 파일 만들기 (`dist/`)          |
| `npm run preview` | 만든 배포용 파일을 로컬에서 미리 보기 |
| `npm run lint`    | ESLint로 코드 검사                    |

## 사용 방법

| 주소              | 화면                           |
| ----------------- | ------------------------------ |
| `/`               | 판례 검색                      |
| `/judgments/{id}` | 판례 상세 (예: `/judgments/1`) |
| 그 외             | 오류 페이지                    |

| 동작                                 | 결과                     |
| ------------------------------------ | ------------------------ |
| 아래 검색창에 검색어 입력 후 Enter   | 판례 검색                |
| 검색 결과의 판례 제목 클릭           | 판례 상세로 이동         |
| 상세 화면 하단 툴바의 맨 오른쪽 버튼 | 인용 판례 패널 열기·닫기 |
| 패널의 "인용된 판례" 클릭            | 인용 판례 목록 펼치기    |
| 목록의 판례 클릭                     | 판례 비교 화면 열기      |
| 비교 화면 오른쪽 위 X                | 비교 화면 닫기           |
| 상단바의 ← 버튼                      | 이전 화면으로 이동       |

## 프로젝트 구조

```text
src/
 ├─ api/                # 판례 검색 API
 ├─ apis/               # 공통 axios 설정, 판례 상세·인용 API, react-query 설정
 ├─ assets/
 │   ├─ icons/          # 화면별로 나눈 아이콘 (sidebar, topbar, search, document, panel, common)
 │   └─ images/         # 로고 등 이미지
 ├─ components/
 │   ├─ common/         # 버튼, 아이콘 같은 공통 컴포넌트
 │   └─ layout/         # 사이드바, 상단바, 본문 틀
 ├─ hooks/              # 조회 훅, 패널 자동 열기 저장 훅
 ├─ pages/
 │   ├─ SearchResultPage/   # 판례 검색 화면
 │   ├─ CaseDetailPage/     # 판례 상세, 인용 패널, 비교 화면
 │   └─ ErrorPage/          # 오류 화면
 ├─ styles/             # 색상·간격·글꼴 디자인 토큰
 └─ types/              # API 응답 타입
```

## 학습 포인트

- **Figma 디자인을 그대로 옮기기**: 글자 크기·여백·크기는 rem, 테두리·그림자는 px로 나눠 쓰고, 실제 화면을 Figma 좌표와 비교하며 맞췄습니다.
- **디자인 토큰으로 스타일 통일**: 색상·간격·글꼴을 Tailwind CSS 4의 토큰으로 정의해 화면마다 같은 값을 쓰도록 했습니다.
- **API 응답과 화면 데이터 분리**: 서버 응답을 화면에 맞는 모양으로 바꾸는 변환 코드를 따로 두어, API가 바뀌어도 화면 코드는 덜 바뀌게 했습니다.
- **서버 데이터 캐싱**: 판례 상세는 조회할 때마다 조회수가 올라가서, TanStack Query로 한 번 받은 데이터를 다시 요청하지 않도록 했습니다.
- **아이콘 정리**: 아이콘을 화면별 폴더로 나누고, 색이나 방향만 다른 아이콘은 하나의 파일로 합쳐 다시 썼습니다.
- **이슈 단위 협업**: 기능마다 이슈를 만들고 브랜치와 PR을 나눠서 작업했습니다.

## 현재 상태

판례 검색, 판례 상세, 인용 판례 패널, 판례 비교, 오류 페이지를 구현했고 백엔드 API와 연결했습니다. Vercel 배포 설정(`vercel.json`)도 되어 있습니다.

남은 작업:

- 검색 화면의 판례 외 카테고리 탭(결정례, 법령 등)과 조건검색·주문유형·키워드 알림 필터 동작
- 판례 상세 하단 툴바의 공유·검색·새 창 열기 등 버튼 동작
- 인용 판례 패널의 판례 정보 외 탭 내용
- 상세 화면 상단바에 실제 검색어 표시 (지금은 "검색어를 입력해주세요")
- 상세 화면에서 검색 화면으로 돌아왔을 때 검색 결과 유지
- 검색 화면과 상세 화면에 따로 있는 사이드바·상단바 하나로 합치기
